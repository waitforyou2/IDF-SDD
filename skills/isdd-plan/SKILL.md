# 制定技术计划

## 目标

把已确认需求拆成小型、按依赖排序的 tracer bullet，并保存方案适配当前代码仓的原因。计划应消除实现歧义，但不得提前编写完整实现。

调用参数：`$ARGUMENTS`

## 执行流程

1. 未明确 change id 时，通过 `/isdd-status` 解析。要求当前状态为 `DEFINED`；验证或评审失败后的返工重新规划也允许 `PLANNED`（对应 `VERIFIED → PLANNED` 返工路径，此时修订已有 plan.md）。
2. 阅读 `spec.md`、`docs/isdd/repository.md`、`docs/isdd/policy.md`、[模式规范](../../references/modes.md)、[CodeGraph 集成规范](../../references/codegraph.md)和[归档契约](../../references/artifacts.md)。
3. 创建 `plan.md`：

   ```bash
   node "${CODEAGENT3_PLUGIN_ROOT}/scripts/sdd.mjs" artifact plan --id <id> --root "${CLAUDE_PROJECT_DIR}"
   ```

4. 在大范围文件搜索前使用 `codegraph_explore`，查询当前端到端流程、精确入口和符号、调用方与被调用方、路由、数据边界、相关测试和影响范围。配置、ADR、过期文件或待同步文件需要直接读取。
5. 为每项行为选择最高且稳定的公共测试 seam。优先复用现有 seam；只有新 seam 同时改善模块深度、局部性或可测试性时才引入。先记录 seam，再规划测试。
6. 完成计划全部章节。把每条验收条件映射到实现工作和验证证据。把工作拆成垂直 tracer bullet：每个任务都必须交付一条窄而完整、可独立验证的行为，并能放入一次聚焦的 Agent 上下文。每个任务必须包含：
   - 任务 id 和明确的依赖边；
   - 精确的仓库相对路径和符号；
   - 交付行为及其对应的验收条件；
   - RED 信号或基线观察、最小 GREEN 结果和最终验证命令；
   - 适用时的文档、迁移、兼容或回滚工作。
7. 只有预重构能明显降低本次需求实现难度且保持仓库持续可用时，才建立独立 prefactor 任务。大范围兼容变更采用 expand-migrate-contract，不得把水平分层工作伪装成垂直切片。
8. 根据模式控制深度：
   - Lite：简要记录当前流程、一个明显方案、一个或少量任务以及现有验证路径。没有有意义备选方案时直接说明。
   - Standard：比较至少一个有意义的备选方案，或说明为什么不存在；记录兼容和回滚方式。
   - Strict：包含迁移与回滚、安全与兼容分析、运行影响和独立架构质疑。
9. 对最终计划进行规格对照检查：确认需求覆盖、未解决占位、路径和符号是否存在、依赖是否成环、跨任务类型或命名是否一致，以及每条命令是否有预期信号。展示前修复所有缺口。
10. 展示拟修改的路径和符号、技术决策、主要取舍、任务依赖图、测试 seam 和主要风险。standard 和 strict 必须获得计划确认。不得把需求确认当成计划确认。
11. 只有校验通过后才能流转：

   ```bash
   node "${CODEAGENT3_PLUGIN_ROOT}/scripts/sdd.mjs" transition --id <id> --to PLANNED --root "${CLAUDE_PROJECT_DIR}"
   ```

## 完成条件

- 计划描述了经过验证的当前实现。
- 每条验收条件都映射到实现工作和证据。
- 已定位受影响模块、符号、接口、调用方和测试。
- 任务为垂直切片，按依赖排序，可独立验证，并能放入一次聚焦上下文。
- 测试 seam 和最新证据命令明确。
- 按模式深度记录了备选方案和有意义的取舍。
- 适用时已处理失败、兼容、迁移和回滚风险。
- `plan.md` 通过 `PLANNED` 状态校验。

## 禁止行为

- 编写没有仓库具体符号和路径的通用检查清单。
- CodeGraph 已返回当前源码和调用链后，又重复进行大范围检索。
- 把无关清理工作加入当前计划。
- 在需要确认的计划尚未确认前开始实现。
- 编写只有“增加校验”之类描述，却没有路径、符号、行为和验证信号的任务。
- 在计划中嵌入容易在 build 前过期的推测性完整实现代码。
