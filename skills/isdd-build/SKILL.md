# 编码实现

## 目标

在不扩大范围的前提下执行已批准计划，使用成本最低且可信的反馈循环，并如实保留最终代码偏离原设计的情况。

调用参数：`$ARGUMENTS`

## 执行流程

1. 解析 change id，要求当前状态为 `PLANNED`。阅读 `spec.md`、`plan.md`、`docs/isdd/policy.md` 和[工作流契约](../../references/workflow.md)。
2. 检查 `git status --short` 和相关 diff。所有预先存在的变更都属于用户，不得丢弃、暂存、提交或重写无关内容。
3. 确认计划仍符合当前代码。精确符号和结构问题使用 `codegraph_explore`，不得重复 `plan.md` 已保存的大范围分析。
4. 按依赖顺序逐个实现 tracer bullet。每项行为变更或缺陷修复都在已确认 seam 上执行 RED-GREEN-REFACTOR：
   - RED：编写或选择最小行为测试，实际运行，并确认它因为预期原因失败。修复缺陷时，修改生产代码前必须先复现报告的问题。
   - GREEN：完成能够通过新测试的最小完整生产代码，不得混入无关清理。
   - REFACTOR：在相关测试保持通过的前提下，简化命名、重复和模块边界。
   纯文档、生成内容或不改变行为的配置，可以改用确定性的前后对比；必须记录为什么 TDD 不适用。
5. 遇到不能立即解释的失败时，按系统化方式调试：复现、最小化、提出一个可证伪假设、收集证据、修复根因并增加回归测试。不得同时堆叠多个猜测性修复。
6. 每个切片完成后运行成本最低的相关检查；所有切片完成后运行仓库规定的完整检查。按仓库策略要求执行类型检查和 lint。不得根据预期结果声称命令通过。
7. 只有计划证据实际通过后才能把任务标记为 `[x]`。现实需要改变方案时，保留原计划，并在 `实际实现偏差` 中记录偏差、证据和原因；没有有意义偏差时写 `无`。
8. 遇到阻塞时，只记录阻塞原因，不改变生命周期状态：

   ```bash
   node "${CODEAGENT3_PLUGIN_ROOT}/scripts/sdd.mjs" block --id <id> --reason "<原因>" --root "${CLAUDE_PROJECT_DIR}"
   ```

9. 未获得独立明确授权时，不得 commit、push、创建 PR、merge 或 deploy。
10. **留白共建执行协议（仅当 `spec.md` 的 `learning_mode` 为 `co-build` 或 `both` 且 `plan.md` 标记了 `共建槽位：Human` 时触发）**：
    - AI 先完成 90% 的非共建切片、外围样板、接口定义与覆盖该槽位的失败单测（RED），实际运行确认因目标函数抛出 `TODO(human)` 而精准报红。
    - 在目标函数内留下清晰的施工单注释（`// TODO(human) [xingyun-sdd co-build: <任务ID>]`，写明目标、2–3 条不变量约束、可用依赖/API 线索及本地单测命令），在纯 CLI 终端输出「施工卡片」（精确 `文件路径:行号` 与单测命令）后暂停等待开发者编码。
    - 开发者回到终端后支持 4 种交互，其中提示与点评**必须派发独立只读 Subagent `sdd-cobuild-coach`**（避免污染主会话上下文）：
      - `hint` / `hint 2` / `ask <问题>`：由 `sdd-cobuild-coach` 提供方向线索或伪代码骨架，绝不直接剧透最终代码。
      - `takeover`：开发者临时没空时由 AI 接管补全，并简述实现差异。
      - `done` / `check`：AI 运行对应单测；未通过时只把失败原因翻译成人话并指向对应代码行，让开发者自行修到绿灯；转绿后派发 `sdd-cobuild-coach` 输出「黄金 2 分钟」对比点评（肯定亮点 + 最多 1–2 条改进 + 精简对照 Diff），由开发者自主决定保留原写法、自行微调或采纳优化。
    - 完成后，将开发者亲手编写的文件路径及精确行号写入 `.isdd-learn/<id>/cobuild-lines.json`（供后续研读本自动渲染 `✦ 亲手共建` 烫金标线），并调用 `scripts/learn.mjs sync` 将本次实操知识点升级为 `practiced` 级别写入 `~/.xingyun-sdd/learning-profile.yaml`。
    - 流转到 `BUILT` 时，`sdd.mjs` 会自动扫描实现文件，若仍残留任何 `TODO(human)` 标记将被硬门禁拦截。
11. 所有计划任务完成后才能流转：

   ```bash
   node "${CODEAGENT3_PLUGIN_ROOT}/scripts/sdd.mjs" transition --id <id> --to BUILT --root "${CLAUDE_PROJECT_DIR}"
   ```

Java Spring MVC 切片调用 [isdd-api-test write](../isdd-api-test/SKILL.md)，按同一份批准计划编写 UT 与 MockMvc 组件测试，保留业务服务，替换数据库、Redis、MQ 和远程客户端。优先复用已有测试设施，断言确实依赖状态时才随用例就近编写所需的 Fake。纯补测以 audit 缺口为基线，新增行为先看到预期失败再转绿。

## 完成条件

- 所有实现任务已完成，或计划已显式修订。
- 每个行为切片都有实际观察到的 RED 信号和通过的 GREEN 证据，或记录了合理例外。
- 代码和测试满足已定义范围，没有无关清理。
- 相关本地检查全部通过。
- 实际实现偏差已如实记录。
- 范围内不存在调试代码、未跟踪临时文件或未解决阻塞。
- `BUILT` 状态校验通过。

## 禁止行为

- 未阅读已批准需求和计划就开始修改代码。
- 因为附近重构看起来方便而扩大范围。
- 重写原计划以隐藏实现偏差。
- 未运行测试就声称测试通过。
- 存在未完成任务时推进状态。
- 未获得失败测试或基线信号就编写生产行为，然后补写无法失败的测试。
- 存在稳定公共 seam 时，仍 mock 内部协作者或测试私有实现。
- 未确认任何假设就同时尝试多个修复。
