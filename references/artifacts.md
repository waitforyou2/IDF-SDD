# 归档契约

`docs/isdd/changes/` 下的变更级归档必须与业务代码一起提交。仓库级辅助文档（`repository.md`、`repository.yaml`、`policy.md`）和 `.codegraph/` 不提交，每次 init 重新生成。

## 仓库级辅助文档（本地，不提交）

- `repository.yaml`：识别出的工程命令、图谱提供方和工作流设置，作为机器可读配置。
- `repository.md`：经过人工确认的架构、领域语言、决策索引、边界、命令、规范和关键流程。
- `policy.md`：由团队维护的模式、确认、证据和安全规则。每个阶段开始前都必须阅读。

## 变更级归档

- `spec.md`：记录为什么需要变更、范围与非目标、验收条件、风险、假设、模式和权威状态。
- `plan.md`：记录当前实现分析、选定方案、备选方案、影响、按依赖排序的垂直切片、测试 seam、回滚和实际偏差。
- `verification.md`：记录验收与证据映射、实际执行检查、CodeGraph 影响分析、相互独立的需求符合度与工程质量发现、限制和结论。
- `delivery.md`：记录评审标题与正文、归档链接、发布与回滚说明和外部交付引用。

## 编写规则

- 记录事实和决策，不记录 Agent 对话流水账。
- lite 模式保持精简，但不得缺少要求内容。
- 符号和路径使用仓库相对路径。
- 记录拒绝有意义备选方案的原因。
- 使用 `repository.md` 中的统一术语；领域语言确实变化时同步更新术语表。
- 任务必须包含具体路径、符号、依赖边、测试 seam 和证据命令，但不得嵌入推测性的完整实现代码。
- 实现偏差追加到 `plan.md`，不得改写原建议来伪装计划从未变化。
- 保留失败验证证据；只有重新执行失败检查后才能更新最终结论。
- 归档中不得出现凭据、令牌、私钥、客户数据或未脱敏生产日志。

使用插件模板和验证器。只有标题或仍包含占位内容的章节，不满足完成条件。
